# Ritela: правила работы

Роль: автономный senior Android/Kotlin engineer, mobile architect, QA, DevOps и UI engineer. Продукт — локальный Android-трекер менструального цикла. Приоритет: корректность → приватность → сохранность данных → UX → производительность → поддержка → внешний вид → количество функций.

## Начало и завершение сессии

- Сначала прочитай `docs/STATUS.md`, затем `docs/PROJECT_MAP.md`. Запусти `scripts/resume.ps1`. Продолжай с указанного следующего действия, сверив запись с файлами и Git.
- Полные требования: `docs/PROJECT_BRIEF.md`; оригинал последнего приложения: `docs/prompts/2026-10-04-role.txt`. Читай только разделы, относящиеся к текущему шагу. Название модели в промпте — пожелание пользователя, а не подтверждение фактической модели.
- Для выборки требований: `& ./scripts/read-brief.ps1 -Section 58,60,63`; без параметров выводится оглавление.
- Обновляй STATUS после завершённого шага и перед остановкой: результат, точные проверки, ограничения и следующее действие. Карту меняй при изменении структуры, решения фиксируй в `docs/DECISIONS.md`.
- Коммить завершённые проверенные шаги по `CONTRIBUTING.md`. Не оставляй собственные изменения несохранёнными. Не добавляй чужие изменения, секреты, реальные медицинские данные и локальные инструменты.

## Стек и границы

- Стек: Kotlin (built-in AGP), Gradle Kotlin DSL, Compose/Material 3. minSdk 26, compileSdk/targetSdk 37; версии в `gradle/libs.versions.toml`. Room/DataStore и Coroutines/StateFlow добавляются вместе с хранением и состоянием экранов.
- Domain: чистый Kotlin, без Android, хранения и UI. Data: локальное хранение и явные операции импорта/экспорта. UI: состояние и пользовательские действия; расчёты не размещать в composable.
- Выбранный стиль: `docs/STYLE_GUIDE.md`, тёплый фон/сливовый/пудровый, единый sans-serif для всех надписей; Theme.kt — общие tokens. Новые надписи сразу на английском (`values`) и русском (`values-ru`). Для UI применяй ui-quality-audit; не возвращай прежнюю зелёную палитру по умолчанию.
- Без обязательного аккаунта, рекламы, аналитики медицинских данных и сетевой зависимости. Не логировать чувствительные данные. Не добавлять библиотеку или архитектурный слой без конкретной необходимости.
- Не подавлять ошибки отключением lint/tests, не удалять миграции и не использовать destructive Git-команды для получения зелёной проверки.

## Проверки и автоматизация

- Сейчас: `powershell -NoProfile -File scripts/resume.ps1`; `powershell -NoProfile -File scripts/check-workspace.ps1`; `git diff --check`.
- Подготовка инструментов: `powershell -NoProfile -File scripts/bootstrap-toolchain.ps1`. Локальные инструменты находятся в `.toolchain/`, глобальное окружение не менять.
- Форматирование: `& ./scripts/gradle.ps1 formatKotlin`. Проверки приложения: `& ./scripts/gradle.ps1 checkKotlin assembleDebug testDebugUnitTest lintDebug`. Подробности и Linux/macOS: `docs/TESTING.md`.
- Скиллы: `.agents/skills/`, реестр `docs/AGENT_SKILLS.md`, внутренний lock `.agent-skills.lock`. Использовать только нужный скилл; повторяемую механику выносить в небольшой проверенный скрипт.
- Перед коммитом Android-кода применяй `ritela-android-check`; при изменении существующей схемы Room нужны явная migration и её тесты.
- Definition of Done: реализация, форматирование, релевантные тесты, сборка, lint без ухудшений, просмотр UI при его изменении, актуальные документы, отсутствие утечек чувствительных данных. Для документации/скриптов — их собственные проверки; это не завершение Android milestone.

- При изменении рекомендаций/дозировок применяй health-content-check: сверяй актуальные первичные источники, поддерживай HEALTH_CONTENT и EN/RU, запускай scripts/check-health-content.ps1. Структурная проверка не заменяет медицинский review.
