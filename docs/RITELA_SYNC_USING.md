# Подключение и автоматические обновления

2026-10-16. Для нового мастера и автообновлений обновить приложение на каждом
телефоне. Для двух профилей одного телефона достаточно одного обновления APK;
активация выполняется отдельно в каждом профиле. Интернет по умолчанию выключен. Коды закрытого пилота
выдаёт оператор: один одноразовый код на профиль. Публичной регистрации нет.

## Подключение

1. На каждом профиле открыть Настройки → Синхронизация и явно активировать пилот.
   В мастере добавления контакта есть переход к этой форме.
2. Создать приглашение, передать файл второму участнику и открыть в его профиле.
3. Сравнить код проверки и подтвердить контакт. Вернуть ответ первому участнику,
   подтвердить там и передать завершающий ответ обратно. Это прежняя взаимная
   проверка личности; имена сами по себе доверие не подтверждают.
4. Мастер включает публичные сертификаты и зашифрованные настройки доставки
   в приглашения; оставшийся служебный обмен идёт через relay автоматически.
   Отдельные два setup roundtrip больше не нужны для новых приглашений.

При уже подключённом интернете обычная отправка не открывает выбор файла/Bluetooth.
Без готового маршрута прежний ручной обмен сохраняется. Принятие контакта не
разрешает отправку медицинских записей: категории выбираются отдельно.
Если контакт создан старой версией, повторно обменяться актуальными приглашением
и ответом или использовать прежний явный setup. При истёкшем маршруте требуется обновить
подключение тем же мастером; TTL пилота остаётся до семи суток. Самопроизвольной
смены доверенного устройства и бесконечной доступности не обещается.
Секреты маршрута не находятся в открытой части приглашения: используется прежний
шифрованный partner envelope. Приглашение ограничено 32 KiB; обычные manual packet
и интернет-лимиты не расширены.

Без сети или при временной ошибке relay мастер сохраняет ручное подключение:
служебная сетевая часть может остаться незавершённой. Сохранённое согласие на
интернет не блокирует обмен файлами. Для завершения интернет-подключения повторно
обменяться приглашением и ответом, когда сеть и relay снова доступны.

## Однократный выбор автообновлений

В переписке нажать «Поделиться данными», выбрать историю месячных, прогнозы и/или
нужные поля дневника, проверить получателя и состав. При готовом интернете доступно
«Автоматически обновлять этот выбор». Переключатель изначально выключен: он означает
отправку подтверждённого пакета и отдельное разрешение будущих изменений этого выбора.

Получателю приходит запрос в чат. Нажатие «Разрешить выбранные обновления» один раз
подтверждает автора и выбранный scope. Затем baseline и последующие изменения/
удаления автоматически поступают в отдельную полученную проекцию и в чат.
Собственные записи получателя не заменяются. Draft и библиотека Doodles автоматически
не отправляются. При изменении авторского устройства действует прежний fencing:
импорт личности не активирует нового автора автоматически.

Доступ закреплён за ID текущих выбранных полей. Новые разделы/теги не включаются
сами. Обычная разовая отправка не расширяет автонабор; для изменения автонабора
нужно вновь явно включить переключатель с новым выбором и получить подтверждение.
Отдельное короткое послание и прикреплённый Doodle не становятся частью дневника.
Остановить будущие автообновления можно в сведениях о контакте или приостановкой
его записей в очереди. Это не удаляет уже переданные копии.

## Скорость и статусы

Если отправитель вернулся после истечения временной резервации baseline, приложения
обновляют её по уже сохранённому разрешению: тот же автор, pairing context, epoch
и тот же набор полей. Новый автор или расширенный выбор так не подтверждаются.
Обновление резервации не создаёт нового запроса согласия в чате. При истечении
всех маршрутов сначала восстановить подключение мастером; сохранённый автонабор
продолжит работать без повторного согласия на те же данные.

Подтверждённая отправка немедленно запускает upload с сохранением server backoff;
исчерпание foreground fetch budget не блокирует сам upload. При открытии профиля
проверяются входящие. Пока приложение RESUMED, активная переписка проверяется
адаптивно (5/15 секунд, при бездействии и на остальных экранах — 60 секунд).
На профиль сохраняется bucket 24/refill 15 s и ceiling 264 foreground checks/hour;
смена профиля/вкладки не сбрасывает бюджет. STOPPED останавливает loop/HTTP.
В фоне остаётся WorkManager раз в час и durable work после локального изменения.
Doze/OEM, отсутствие сети и квоты могут увеличить задержку.

В чате различаются очередь, принятие сервером, подтверждённое E2E получение,
ошибка с нормализованной причиной и повтором. «Принято сервером» не означает
получения другим профилем. Retry не обходит Retry-After. Неготовый/истёкший маршрут
имеет отдельную причину. Подробности очереди доступны в настройках синхронизации.

При проверке на одном телефоне сначала дождаться принятия сервером в отправляющем
профиле, затем открыть получающий. Неактивный профиль не открывает свою БД и не
отправляет запросы. После возврата в отправляющий профиль придёт E2E подтверждение.
Реальная проверка production/двух устройств, CPU/квот и independent security review
остаётся отдельной; локальные synthetic tests её не заменяют.
