# Решения

2026-10-17: по новому явному запросу закрытые activation tokens заменены в основном
flow автоматической регистрацией после явного internet consent. Код/аккаунт не
нужны; запрос подписан новым локальным ключом, ключи/identity не заменяются.
Старые токены поддерживаются для совместимости, AUTO_REGISTRATION закрывает
новые регистрации без кода. Per-IP edge limiter дополняет атомарный предел 100
устройств; это не полноценная защита открытой массовой регистрации. Схемы Room/D1
и runtime secrets прежние. Отзыв/recovery не обходится повторной регистрацией.

Для автообновлений исходящий запрос показывается в чате с ожиданием/одобрением,
состояние одобрения обновляется по Room Flow независимо от очереди исходящих.
Скрытие пузыря не отзывает сохранённое согласие. Journal watermark будит upload
в RESUMED профиле через conflated channel; fetch и backoff по-прежнему ограничены.
Полная исходящая цепочка Android воспроизведена на local workerd/D1 по отдельному
synthetic transcript с публичными ключами/подписями и тестовыми ciphertext/capability.

2026-10-16: форма нового обмена использует только текущие поля/теги дневника,
а не historySections: каталог совместимости не должен предлагать удалённые или
неиспользуемые поля. Новый выбор фиксируется в ID активных тегов; прежние grants,
auto scope и декодирование архивов не меняются. Выбор дневника необязателен и
свёрнут; нет общего массового согласия на дневник. Отдельный legacy setup остаётся
в технических сведениях, основной путь — мастер приглашения в контакте.

Резервация baseline обновляется служебным запросом без нового user approval
только при точном совпадении сохранённых context/grant/epoch/scope. Source отменяет
неподтверждённые прежние drafts, сохраняет journal, создаёт новый baseline с новыми
ID/sequence; прежний ciphertext не перепаковывается под тем же ID. Record upload
не использует истёкшую резервацию; STORED baseline ждёт E2E без повторного upload.
Metadata follow-up выполняется после освобождения pump mutex, оставаясь дочерней
частью tracked job: close/switch отменяет и дожидается также follow-up HTTP.
Без доступного AUTHOR route MORE не создаёт hot loop; control-обмен использует
имеющийся message route. Истечение всех routes требует мастера подключения.

2026-10-16: мастер file invitation объединяет pairing и relay setup. Открыто
передаётся только подписанный public transport certificate; capability offer
находится в прежнем зашифрованном partner packet внутри приглашения. Лимит 32 KiB,
публичной регистрации нет. Pending peer certificate проверяется криптографически,
но не даёт route/data access до взаимного подтверждения. Служебный ответ уже идёт
через relay, HPKE bytes записываются до enqueue/HTTP.

Auto consent — отдельный, изначально выключенный выбор владельца для конкретного
peer/device и фиксированных ID полей. Получатель подтверждает автора/selection один
раз в чате. Approval с context/epoch/scope записывается до активации author; будущие
пакеты проверяются по нему. Обычный manual scope не расширяет автонабор, старый
автонабор сохраняется независимо от разового выбора. Автор generation >1 не
активируется этим flow. Журнал/deltas/DELETE применяются атомарно и создают chat
snapshot только после изменения projection; повтор не создаёт чат-дубль.
Room 11 и прежние миграции не меняются. Relay API/Cloudflare deployment не меняются.

2026-10-16: foreground delivery выполняется при RESUMED активного профиля;
подтверждённый Send инициирует pump немедленно. Token bucket сохраняется отдельно
по профилю: capacity 24/refill 15 s, ceiling 264/hour; смена профиля/вкладки не
сбрасывает бюджет. Retry сохраняет server Retry-After; PAUSED validation можно
повторить явно. Статус чата различает queue/STORED/E2E ACK/error, metadata берётся
из Room и не помещается в wire protocol.

2026-10-16: artifact checks Sync требуют INTERNET/ACCESS_NETWORK_STATE и явного
cleartext=false; прежний запрет любых network permissions устарел. Runtime consent
доказывают отдельные тесты, а не manifest. Relay local checks включены в CI и
release до signing без deploy/credentials. Метрики snapshot — только числовые
границы, без payload/идентификаторов/секретов. Локальная recovery matrix не заменяет
device update/production E2E/CPU/security review; backout сохраняет Room и историю,
не применяет destructive downgrade.

2026-10-15: настройки Sync показывают только уже доступные действия: ручной режим, metadata-only очередь, состав категорий/вложений, local cancel/pause и отзыв сохранённого интернет-согласия. Enable/setup/relay deletion и auto consent не имитируются до runtime этапов 5–6. Cancel сохраняет исходное послание; pause отдельно выключает auto-send одному peer/device. Off атомарен с отменой локальных pending/leases, но не удаляет STORED bytes и не заявляет remote erasure. Room 10 entities/migrations не меняются; consent и credentials при открытии настроек не создаются.

2026-10-15: подтверждённые message send intents хранятся отдельно от sequenced author outbox: Room 9→10 добавляет только sync_message_intents с message ID ledger, pairing/grants/content digests и PENDING_WRAP/BLOCKED/ACKED/CANCELLED. Это исключает расход sequence автоизменений на послания/квитанции. Payload остаётся в существующем PartnerMessage; запись намерения атомарна с confirm/send, без backfill истории при opt-in. PENDING_WRAP не является HPKE ciphertext или relay storage. Старые manual packet/saved Doodle budgets сохраняются; интернет-лимит блокирует только намерение, без усечения локального содержимого. Завершение runtime этапа 5 требуется перед реальной отправкой.

2026-10-15: первая часть этапа 5 — платформенный HttpsURLConnection без новой HTTP зависимости: exact HTTPS origin allowlist, redirects/compression off, bounded response и активный disconnect при cancellation. Callback свежей проверки profile/global/peer/lease обязателен перед connect. Fetch не продвигает checkpoint и не отправляет storage ACK до durable authenticated apply верхнего уровня. Runtime/WorkManager/permissions добавляются следующим проверяемым шагом, поэтому приложение пока остаётся без сетевого допуска. Старый manual ciphertext не получает автоматического internet fallback.

2026-10-15: этап 4 использует Tink 1.23.0 HPKE base с обязательной внутренней подписью existing device и separate per-profile API/HPKE vault; собственный ECDH-wrapper и ratchet не добавляются. Static recipient compromise не даёт forward secrecy. Relay author CAS требует двух API signatures, routes неизменяемы/до 7 дней, revoke закрывает доступ сразу, большие ciphertext queues удаляются bounded cleanup. Recovery D1 требует внешней epoch и operator ledger. Локальные meta показали 40 writes/upload+ACK до GC: ориентир пилота снижен до 50 участников до deployed CPU/meta, технический registration cap 100 не является обещанием Free ёмкости. Production binding/deploy отсутствуют.

2026-10-15: identity import сначала фиксирует RECOVERY_REQUIRED в Room и только затем сохраняет новые vault keys. Такой порядок не позволяет crash между файловой записью и Room metadata открыть bootstrap нового автора; v1 pairing остаётся доступным. В inbox pending/applied/discarded различаются явно: подтверждение преемника и очистка неполного baseline не превращаются в application ACK. Синхронный E2E ACK до завершения transport.store считается успехом только по точному уже подтверждённому PartnerMessage/envelope, не восстанавливает очищенный outbox и не продлевает lease.

2026-10-15: этап 3 отделяет application v2 от cryptographic wrapper. Явный ручной suite использует существующий JCA envelope с новыми kind SYNC_CAPS/SYNC; интернет не получает fallback к этому suite, Tink HPKE остаётся этапу 4. Capabilities привязаны к обоим pairing nonce и устройству. Author grant подтверждается отдельно от доверия контакту; successor требует обе подписи и previous digest. Старое устройство сначала атомарно RETIRED с сохранённым идемпотентным handover; нового автора без будущего relay fence активировать нельзя. Received projection имеет собственные таблицы/checkpoint и приоритет над v1 даже после очистки. Baseline собирается полностью, scope меняется только новым epoch; журнал ID/digest сохраняется после удаления и ограничен отказом при заполнении, без опасного автоматического GC. Подробности — architecture/RITELA_SYNC_STAGE_3.md.

2026-10-15, этап 2 Sync: журналирование находится в транзакционных DAO wrappers с общим ChangeRecorder, поэтому обычная запись и import охвачены одинаково без зависимости от Flow collector/активного UI. Room 7→8 только добавляет пять таблиц. Source sequence/floor локальны; draft использует per-link versions и digest только разрешённой projection, не раскрывает глобальный счётчик запрещённых событий. Per-link projection state отличает снятие ранее переданного тега от никогда не разрешённой записи. Для неинициализированного opt-out получателя каждые 256 изменений сохраняется только latest/tombstones; активные checkpoints/pending work защищают compaction. Обязательные encoder/transport ports не имеют production реализации; fake bytes только в тестах, STORED не означает E2E delivery. Нет автоматического consent/author activation/реального транспорта; multipart/wire/apply/E2E ACK и освобождение подтверждённых outbox bytes относятся к следующим этапам. Queue limits блокируют материализацию, сохраняя собственные записи. Последнее уточнение пользователя ограничило текущую работу этапом 2.

2026-10-15, реализация этапа 1 Sync: по явной команде пользователя выполнены модели/инварианты и Room 6→7. Миграция только добавляет четыре служебные таблицы и off/uninitialized singleton defaults, без backfill, чтения vault, нормализации старых JSON или автоматического согласия. Fresh defaults создаёт транзакционный INSERT IGNORE при первом локальном чтении. Raw flags хранятся как Int 0/1, неизвестные/непроверенные metadata дают типизированный отказ; SQL ошибки остаются ошибками хранения. DAO/store намеренно не предоставляют activation/transfer/consent mutation до разработки соответствующего протокола. Tag keys квалифицированы sectionId/tagId, budgets считаются по bytes. Старые сущности/миграции, ключи и manual wire не меняются; модели author grants структурные и не доказывают проверку подписи или distributed fencing. Этап 2/сеть/облако в этот объём не включены.

2026-10-15, уточнение Sync после принятия архитектуры за основу: сохраняется single-author, закрытый пилот использует activation tokens, публичная регистрация отложена. Рекомендованы adaptive foreground fetch с отдельным бюджетом и редкий background WorkManager, HPKE через Tink вместо собственной ECDH/HKDF/GCM схемы, author-generation fence с явным восстановлением и три независимых результата отзыва/удаления. Интернет off до opt-in, медицинские данные/секреты не логируются, автоматический Bluetooth/BLE не входит в объём. [План этапа 1](architecture/RITELA_SYNC_STAGE_1.md) ограничивает будущую миграцию четырьмя неактивными служебными таблицами без переписывания legacy данных. Эти документы уточняют дизайн; пользователь явно не разрешил начинать реализацию.

2026-10-15, границы аудита Sync: по новому заданию подготовлен только [план](architecture/RITELA_SYNC_PLAN.md), без изменения кода и развёртывания сервера. Существующая D1 учтена как предоставленный пользователем ресурс, но не проверена и не изменена. Предложения о single-author, v2, внешнем шифрованном wrapper, TTL и relay API требуют согласования; они не заменяют действующий ручной обмен и не являются утверждёнными архитектурными решениями. Реализация начинается только после согласования плана.

2026-10-13, удаление сообщений: Room v6 добавляет hiddenFromChat=false через явную миграцию 5→6. У полученного DATA, используемого вне переписки, по умолчанию скрывается только строка чата; payload остаётся источником главной и календаря. Флажок в меню каждый раз выключен. Явное удаление данных очищает body/envelope и даёт fallback на предыдущий непустой DATA. Исходящие сообщения и дудлы очищаются локально; ID/личность/устройство/тип сохраняются для защиты от повторного импорта и проверки поздних квитанций. ACK/OPENED не обновляют скрытую строку. Собственные таблицы, библиотека дудлов, lastSelection и удалённое устройство не затрагиваются. Wire format и обычный backup не меняются.

2026-10-13, окно отправки: сохранённый packet не является событием открытия. Только успешное явное действие показывает окно, в том числе повторно для того же ID. Запрос связан с ревизией профиля/чата; смена контекста и уход с экрана отменяют показ позднего результата. Закрытие сохраняет ожидающий пакет, системный chooser не доказывает доставку.

2026-10-13: послание и один дудл передаются внутри существующего DATA-пакета, без второго сообщения. Сохранённые дудлы — локальный файл профиля, не Room и не медицинские записи; максимум 15, порядок по числу успешных отправок. Старый получатель отклоняет неизвестные поля note/doodle, поэтому оба приложения должны быть обновлены. Отдельный DOODLE-пакет остаётся.

2026-10-13: файловый обмен не требует второго файла для подтверждения доставки или открытия. Получатель сохраняет проверенный DATA/DOODLE и не готовит ACK; открытие дудла локально и не создаёт OPENED-файл. Bluetooth по-прежнему возвращает ACK в текущем соединении, а пришедший ACK/OPENED по-прежнему обновляет статус. Открытие системного меню отправки само по себе не ставит «Доставлено».

2026-10-13: PartnerPreferences.homeSelected — отдельное профильное поле DataStore для главной/календаря; selected остаётся выбором переписки. Если новый выбор ещё не задан или удалён, используется первый контакт, независимо от selected. Общие CycleForecastHero/CycleOrbitDetails принимают готовые даты/состояние; собственный режим использует прежний анализ, партнёр — authenticated snapshot без PredictionEngine и выдуманных статистик. День/фаза/отсчёт у партнёра привязаны к asOf, не продвигаются часами получателя. Нет cycleLength/asOf — нет придуманной интерактивной орбиты; переданная дата остаётся видимой. Даты фокусирования вычисляются относительно снимка, фаза фокуса — из его duration/ovulation; текущая фаза берётся как передана. Фертильный календарный ориентир −5…+1 сохраняет приоритет фактов/месячных. Статьи переиспользуют существующий каталог без дневника другого пользователя и без изменений медицинского контента.

2026-10-13: фолликулярная область отображается кэшированными частицами вдоль существующего OrbitGeometry.path до OVULATION.progress вместо отдельной планеты. Цвет зависит от положения вдоль дуги; scatter детерминированный, без новой анимации. Геометрия проверяет отступы от солнца/овуляции и принадлежность области нажатия к дуге. Старый FOLLICULAR touch target сохранён для доступности, нажатия по остальной пыли вызывают ту же OrbitPhaseInfo. Удалён hero_orbit_info вместе с показами в справках и параметром includeOrbit. Медицинские тексты и алгоритм не менялись.

2026-10-13, категории обмена: PERIODS означает полную записанную историю; FORECASTS включает последнюю по startDay запись periods для контекста прогноза, сохраняя независимый выбор истории. Для FORECASTS без PERIODS validateData допускает максимум одну запись periods, для истории сохраняет предел 10000. Совместный выбор не дублирует запись. Алгоритм прогнозов и горизонт до today.plusYears(1) не изменены. Ключи wire-пакета/схема Room сохранены, однако прежний строгий клиент отвергает новый FORECASTS-only пакет с periods; обе стороны должны обновиться.

2026-10-13, локализация диалогов: JournalDialog передаёт текущие профильные LocalContext/LocalConfiguration/LocalResources во внутреннюю композицию Dialog вместе с плотностью. Иначе Dialog возвращает локаль Activity, и при русском языке профиля/английской системе названия месяцев отображаются на английском. Проверка охватывает форму месячных и вложенный выбор месяца.

2026-10-13: ручной обмен подтверждается одним действием после выбора и предпросмотра. PartnerIdentity.lastSelection хранится в существующем directory JSON, независимо для каждой личности, без изменения схемы Room. Отсутствующее поле в старой записи означает пустую начальную форму, grants не используются как предпочтение. Полные разделы фиксируются текущими ID тегов. confirmData сохраняет зашифрованный пакет, lastSelection и соответствующие grants в одной транзакции под mutex; ошибка не меняет выбор. prepareData/retry продолжают проверять grants, настройки приложения исключены только из новых пакетов. Это заменяет прежний двухуровневый UX разрешений.

2026-10-12, messenger: DATA/DOODLE отображаются одной хронологической лентой по локальному received, ACK/OPENED остаются только обновлениями исходных сообщений. Из-за отсутствия доказательства отправки через внешнее приложение нельзя автоматически присваивать «Отправлено» или «Доставлено» после открытия share sheet. Идентификаторы/права неизменны; интерфейс не добавляет текстового протокола. При первом обмене возможен явный union сохранённых grants с ровно выбранным набором, затем prepareData по-прежнему проверяет фактическую передачу; отказ не сохраняет draft. Чувствительные категории не включаются автоматически. Основной вход разрешений относится к выбранной личности в диалоге, а для общего профиля сначала выбирается конкретная личность.

2026-10-12, Partner UX: режим/выбор контакта в профильном DataStore, получатель использует asOf/cycleDay/phase и переданные годовые даты без PredictionEngine. Необязательные FORECASTS metadata читаются новым клиентом; старые строгие клиенты требуют обновления для новых пакетов. Прежний ShareScope поддерживает сужение DIARY/полной секции до отдельных тегов, не расширяя соседние grants. ACK/OPENED скрыты из ленты, но остаются в протоколе. Active peer требует аутентификации и сбрасывается при закрытии; наличие доверия/bonded device не доказывает присутствие. BLE исследован, публичные постоянные ID не допускаются; новый beacon/сканирование не включены без проверенного ephemeral-протокола. Подробности: PARTNER_UX_REWORK.md.

2026-10-11, уточнение Partner: по явному запросу пользователя минимальный пароль переносимой личности снижен с 8 до 4 символов в UI и общей проверке PBKDF2. ## 2026-10-11: определения тегов сохраняются отдельно от выбора

Удаление тега/раздела изменяет только доступный выбор, его определение остаётся в JSON-архиве структуры. Восстановление тегов не очищает исторические selections; актуальные определения имеют приоритет в отображении и настройке сердечка. Новые настроения сохраняются в существующем custom JSON без смены Room-схемы. Метаданные «Без проникновения» не меняют PredictionEngine, не являются оценкой риска беременности и используются только для контурного/красного символа в календаре. Неразрешимое имя старого удалённого ID получает локализованную подпись вместо технического UUID.
## Подключение без QR, 2026-10-12
