Ты работаешь над Android-приложением Ritela на Kotlin + Jetpack Compose.

Нужно провести полноценный UI polish главного экрана и календаря.

Перед началом обязательно изучи:

docs/ui/ritela_main.png
docs/ui/ritela_calendar.png
docs/ui/Ritela_UI_Kit.png
docs/ui/style_brief.md
docs/ui/orbit_spec.md
docs/ui/implementation_brief.md

Эти материалы являются visual source of truth для задачи.

Сначала также изучи существующий код Home, Calendar, theme/design system и связанные ViewModel/state classes.

Не переписывай бизнес-логику и архитектуру без необходимости.

Основная цель:
приблизить реальный интерфейс приложения к дизайну из docs/ui, сохранив нативный Jetpack Compose, производительность, accessibility и существующую функциональность.

Целевой стиль:

celestial-botanical premium minimalism

То есть:
- премиальный;
- спокойный;
- мягкий;
- атмосферный;
- слегка фантазийный;
- botanical + celestial;
- без astrology/esoteric vibe;
- без ощущения generic Material demo.

ВАЖНО:
не пытайся буквально воспроизвести растровый concept art.
Переведи его визуальный язык в аккуратные native Compose components.

--------------------------------------------------
1. СНАЧАЛА ПРОВЕДИ АУДИТ
--------------------------------------------------

Перед изменениями:

1. Найди существующие Home и Calendar composables.
2. Найди theme/colors/typography/shapes.
3. Найди текущую реализацию orbit visualization.
4. Найди current navigation.
5. Определи, какие части можно переиспользовать.
6. Найди визуальные проблемы текущего Home/Calendar.

Создай краткий план работ и сразу приступай.

Не останавливайся после плана.

--------------------------------------------------
2. DESIGN SYSTEM
--------------------------------------------------

Приведи UI к единой дизайн-системе.

Создай/обнови централизованные tokens:

RitelaColors
RitelaTypography
RitelaSpacing
RitelaShapes
RitelaMotion

Не размазывай magic dp/sp/colors по файлам.

Используй screenshots/UI Kit как направление.

--------------------------------------------------
3. HOME
--------------------------------------------------

Главный экран должен иметь структуру:

Header
Cycle Hero
Primary CTA
Today quick actions
Insights
Articles
Bottom navigation

Hero является единственным сильным atmospheric wow-object.

Всё ниже hero:
- проще;
- чище;
- функциональнее;
- меньше декоративности.

--------------------------------------------------
4. HERO
--------------------------------------------------

Hero должен включать:

День N цикла
Текущая фаза
Orbit visualization
Следующие месячные
Основная predicted date
Prediction range
Countdown

Пример текущих данных:

День 9 цикла
Фолликулярная фаза
2 ноября
30 окт. — 5 нояб.
Примерно через 25 дней

Не дублируй одну информацию несколькими предложениями.

--------------------------------------------------
5. ORBIT
--------------------------------------------------

Следуй строго:

docs/ui/orbit_spec.md

Не делай случайную россыпь кружков.

Не рисуй ломаную/рваную траекторию.

Нужна единая smooth artistic orbit.

Используй Compose Canvas.

Создай отдельную geometry abstraction, например:

OrbitGeometry
CycleOrbitScene
OrbitMarker

Все точки должны вычисляться через одну и ту же геометрию траектории.

Нужно ровно 5 semantic points:

1. cycle start
2. follicular
3. ovulation
4. luteal
5. end / transition

Отдельно:

current-day marker

Sun:
symbolic start/life-energy anchor.

Orbit может быть artistic и слегка асимметричной.

Она НЕ обязана быть физически правильной.

Важно визуальное качество.

--------------------------------------------------
6. ORBIT ANIMATION
--------------------------------------------------

Добавь только мягкую motion-систему.

Orbit:
slow breathing alpha

Current day:
subtle pulse

Sun:
very subtle halo

No rotation.

No fast animation.

No shimmer.

Respect reduced motion / animator scale.

--------------------------------------------------
7. TODAY QUICK ACTIONS
--------------------------------------------------

Вместо сырого текстового блока использовать компактные мягкие tiles:

Настроение
Энергия
Симптомы
Активность
Заметка

Они должны быть небольшими, аккуратными и легко нажиматься одной рукой.

--------------------------------------------------
8. INSIGHTS
--------------------------------------------------

Сделай небольшой набор premium compact insight cards.

Например:

Обычная длина цикла
Вероятная овуляция
Ожидаемая длительность
ПМС / phase-related insight

Не превращай экран в dashboard.

--------------------------------------------------
9. ARTICLES
--------------------------------------------------

Статьи остаются в нижней части главного экрана.

Они должны быть визуально спокойнее hero.

Приведи article cards к той же системе:
- shapes
- typography
- colors
- spacing

--------------------------------------------------
10. CALENDAR
--------------------------------------------------

Календарь должен быть functional first.

Главная идея:

верх:
atmospheric

calendar grid:
clean and readable

Нужны состояния:

normal
today
selected
logged period
predicted period
fertile window
ovulation
out-of-month

Используй систему из Ritela_UI_Kit.png.

Не использовать яркую зелень для fertile window.

Используй мягкий warm ivory / peach / muted tones.

--------------------------------------------------
11. CALENDAR ARCHITECTURE
--------------------------------------------------

Если текущий календарь кастомный и работает хорошо — не переписывай его без причины.

Если calendar grid logic неудобна, можно рассмотреть:
com.kizitonwose.calendar:compose

Но сначала оцени текущую реализацию.

Не добавляй dependency только ради redesign.

--------------------------------------------------
12. TYPOGRAPHY
--------------------------------------------------

Большие даты / branding:
serif feeling.

UI:
clean sans-serif.

Не обязательно добавлять новый внешний font dependency, если текущая система уже близка.

Если используешь новые шрифты:
проверь лицензию и размер приложения.

--------------------------------------------------
13. PERFORMANCE
--------------------------------------------------

UI должен оставаться лёгким.

Не использовать:
- Lottie;
- GIF;
- video;
- expensive blur loops;
- continuous bitmap effects.

Следить за recomposition CycleOrbitScene.

Не пересчитывать Path при каждом frame, если geometry не изменилась.

--------------------------------------------------
14. ACCESSIBILITY
--------------------------------------------------

Orbit декоративная.

Вся важная информация также отображается текстом.

Проверить:
- TalkBack semantics;
- contrast;
- large font;
- touch target;
- reduced motion.

--------------------------------------------------
15. VISUAL VALIDATION LOOP
--------------------------------------------------

Это обязательная часть задачи.

После первого рабочего варианта:

1. собрать приложение;
2. открыть экран;
3. сделать screenshot;
4. сравнить его с docs/ui/ritela_main.png;
5. исправить:
   - spacing;
   - typography;
   - visual hierarchy;
   - colors;
   - surface balance;
   - orbit composition;
6. повторить для Calendar.

Не завершай задачу на первой компилируемой версии.

Сделай минимум один отдельный visual-polish pass.

--------------------------------------------------
16. DO NOT
--------------------------------------------------

Не:
- заменяй весь интерфейс одной картинкой;
- используй PNG как background для UI;
- хардкодь positions под один телефон;
- делай WebView;
- добавляй десятки decorative dependencies;
- удаляй существующую functionality;
- меняй prediction/domain logic ради UI.

--------------------------------------------------
17. TEST / PREVIEW
--------------------------------------------------

Добавь/обнови Compose Previews:

Home
Calendar

Для:
- normal phone;
- narrow phone;
- dark theme;
- large font где возможно.

Если screenshot tooling уже есть — обнови screenshot tests.

--------------------------------------------------
18. DEFINITION OF DONE
--------------------------------------------------

Считать задачу выполненной только если:

- Home визуально намного ближе к docs/ui/ritela_main.png;
- Calendar визуально ближе к docs/ui/ritela_calendar.png;
- общий дизайн соответствует Ritela_UI_Kit.png;
- orbit гладкая и визуально осмысленная;
- есть 5 semantic markers;
- current day отдельный marker;
- hero ощущается как главный wow-object;
- остальной UI менее декоративный;
- календарь остаётся легко читаемым;
- нет regressions существующей functionality;
- build проходит;
- tests/lint не сломаны;
- выполнен отдельный polish-pass.

В финале напиши:

1. какие файлы изменены;
2. какие UI components созданы;
3. какие design tokens созданы/изменены;
4. что сделано с orbit;
5. как проверял визуально;
6. какие тесты запускались;
7. известные ограничения.
