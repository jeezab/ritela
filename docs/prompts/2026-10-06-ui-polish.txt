Ты senior Android UI/UX engineer, Jetpack Compose engineer и product designer.

Нужно провести качественный UI/UX polish-pass текущего Android-приложения Ritela.

ВАЖНО:
не переписывай интерфейс с нуля;
не ломай текущую структуру продукта;
не меняй без необходимости бизнес-логику;
не добавляй новые крупные feature;
не пытайся сделать приложение похожим на Flo.

Цель:
сохранить уже удачные сильные стороны Ritela и довести интерфейс от уровня хорошего MVP до аккуратного polished consumer app.

Работай по циклу:

inspect
→ identify visual problems
→ implement
→ render/preview
→ compare
→ refine
→ test
→ repeat

Не считай UI-задачу выполненной только потому, что код компилируется.

==================================================
1. ОБЩЕЕ НАПРАВЛЕНИЕ
==================================================

Сохрани текущую визуальную идентичность:

- тёплый off-white фон;
- сливовые акценты;
- приглушённые розовые;
- мягкие шалфейные оттенки;
- спокойный, не медицинский визуальный язык;
- отсутствие рекламного/глянцевого ощущения;
- отсутствие стереотипного "pink women's app";
- минимализм;
- хорошая читаемость;
- тёмная тема должна оставаться сильной частью дизайна.

Не устраивай полный редизайн.

Целевая эстетика:

Material 3
+
редакционная типографика
+
мягкая health-визуализация
+
минимум лишних карточек
+
много воздуха
+
орбита как фирменный визуальный мотив

Интерфейс должен ощущаться спокойным, взрослым, современным и дорогим.

==================================================
2. ГЛАВНАЯ ПРОБЛЕМА: СЛИШКОМ МНОГО КАРТОЧЕК
==================================================

Сейчас слишком много элементов помещено в rounded-card контейнеры.

Из-за этого интерфейс выглядит как набор отдельных UI-компонентов вместо единой композиции.

Нужно уменьшить количество карточек.

Правило:

используй карточку только если элемент действительно является самостоятельным смысловым объектом.

Не оборачивай:

- секцию;
- график;
- заголовок;
- набор двух метрик;

в отдельную большую карточку без необходимости.

Например блок "Ваш цикл" лучше сделать как часть страницы:

Ваш цикл

28 дней
Обычная длина

28–30 дней
Обычный диапазон

[compact sparkline]

без дополнительного большого outer-card.

Оставляй отдельные карточки для:

- hero prediction card;
- значимого insight;
- содержательной статьи;
- отдельного состояния, которое действительно нужно визуально отделить.

==================================================
3. HOME SCREEN
==================================================

Главная сейчас является самым сильным экраном.

Не ломай её структуру.

Нужно сделать её визуально легче и точнее.

Текущий верхний блок слишком тяжёлый:

Ritela
Сегодня
среда, 14 октября 2026 г.

Сократи визуальный вес header.

Предпочтительно:

Ritela                     optional small action

Среда, 14 октября

или аналогично.

Название приложения не должно конкурировать с содержанием экрана.

Полная дата с годом обычно не нужна на Home.

==================================================
4. HERO PREDICTION CARD
==================================================

Hero card оставить главным визуальным центром.

Сохранить:

- день цикла;
- дату предполагаемых месячных;
- диапазон;
- качество/стабильность данных;
- основание прогноза.

Но уменьшить излишние вертикальные отступы примерно на 10–15%.

Карточка должна быть компактнее, но не тесной.

Для русского языка предпочитать:

19 октября

вместо:

19 окт.

Если полное слово помещается красиво.

Иерархия:

24 день цикла

Следующие месячные
19 октября

Вероятно 17–21 октября

История достаточно ровная

Не перегружать мелкими пояснениями.

==================================================
5. ORBIT MOTIF
==================================================

Текущая окружность с точками выглядит слишком похожей на график, хотя медицинского смысла у неё нет.

Нужно решить это одним из двух способов.

ПРЕДПОЧТИТЕЛЬНО:
сделать орбиту фирменным элементом Ritela и придать ей простой понятный смысл.

Например:

- одна активная точка = текущий день цикла;
- остальные точки = условный ход цикла;
- центр = ботанический знак Ritela;
- возможно подпись "день 24 из ~29".

Не использовать орбиту как медицински точное представление фаз.

Она должна быть брендовым визуальным индикатором, а не псевдонаучным chart.

Если смысл дать не получается — сделать её явно декоративной:
тонкая окружность, меньше точек, мягкая непрерывная линия, меньше ощущение data visualization.

Орбита должна стать узнаваемым визуальным мотивом Ritela.

Позже этот мотив должен хорошо переноситься в:

- widget;
- onboarding;
- iconography;
- loading state;
- empty state.

==================================================
6. PRIMARY CTA
==================================================

Кнопка "Отметить месячные" сейчас хорошая.

Оставить её заметной.

Но CTA не обязана всегда занимать огромную ширину.

Если месячные уже идут, заменить CTA на state-based block:

● Месячные идут · день 3

Изменить

То есть action должен зависеть от состояния.

Не показывать каждый день одну и ту же giant CTA без причины.

==================================================
7. TODAY / DAILY LOGGING
==================================================

Текущие маленькие карточки:

Голова
Живот
Энергия

выглядят слишком dashboard-like.

Уйти от набора маленьких "панелей датчиков".

Сделать секцию более человекоориентированной.

Предпочтительный формат:

Сегодня                         +

Спокойное настроение
Небольшая боль в животе
Низкая энергия

или:

Как вы сегодня?

🙂 Спокойно
◌ Без боли
⚡ Низкая энергия

+ Добавить

Главная должна в первую очередь показывать фактически записанные данные, а не каталог потенциальных симптомов.

Все подробности лучше открывать через bottom sheet / add flow.

==================================================
8. INSIGHTS ВМЕСТО DASHBOARD-ГРАФИКОВ
==================================================

Сейчас графики являются одним из самых слабых мест.

Проблема:
они выглядят как диагностические/debug charts.

Если данные одинаковые, например:

28 28 28 28 28 28

линейный график почти ничего не сообщает.

В таких случаях показывать вывод, а график делать вторичным.

Например:

Ваш цикл

28 дней
Обычная длина

Последние 6 циклов отличаются не больше чем на 1 день.

[small sparkline]

То же для месячных:

Обычно 5 дней

Последние 6 записей: 5–5 дней

[small sparkline]

Если данных мало или они одинаковые — не показывать сложный chart.

==================================================
9. SPARKLINES
==================================================

Для небольших исторических данных предпочитать sparkline.

Не использовать тяжёлую grid.

Не использовать оси, если они не нужны пользователю.

Предпочтительно:

- тонкая линия;
- 4–6 точек;
- минимум подписей;
- tooltip/selection при взаимодействии;
- дата только для выбранной точки.

Графики должны выглядеть как часть consumer app, а не аналитической панели.

==================================================
10. БЛОК БОЛИ / ПУСТЫЕ СОСТОЯНИЯ
==================================================

Не показывать пустой chart с текстом вида:

"Здесь появятся отметки дня."

Если данных недостаточно, использовать нормальный empty state.

Например:

Боль и самочувствие

Пока недостаточно записей

Отмечайте состояние несколько дней —
здесь появятся закономерности.

[Добавить отметку]

После появления данных блок может автоматически стать insight.

==================================================
11. INSIGHTS
==================================================

В целом двигать продукт от "покажи мне график" к "скажи мне полезный вывод".

Например:

Наблюдение

За последние 4 цикла боль в животе чаще отмечалась за 1–2 дня до начала месячных.

Подробнее →

или:

Повышенная усталость чаще отмечалась во второй половине цикла.

Графики должны подтверждать выводы, а не заменять их.

Не делать медицинские причинно-следственные утверждения.

==================================================
12. HELP CARDS
==================================================

Секция "Для вас" нормальная по смыслу, но сейчас карточки слишком крупные и похожи на generic content cards.

Сделать компактнее.

Например:

Для вас                         Все статьи

♡ Боль в животе
  Что может помочь
  3 мин

♡ Сон
  Почему он может меняться
  4 мин

Не делать огромные плитки без необходимости.

Источник вроде NHS лучше показывать внутри статьи или как маленький metadata line, но не делать его визуальным центром карточки.

==================================================
17. TYPOGRAPHY
==================================================

Системный sans оставить основным UI-шрифтом.

Но добавить ограниченный display-акцент для:

- Ritela;
- крупной даты прогноза;
- больших числовых показателей;
- возможно крупных section metrics.

UI text должен оставаться neutral sans.

Пример:

Display typography:
мягкая, редакционная, характерная

UI typography:
нейтральная, функциональная, системная

Не менять весь интерфейс на decorative font.

Не ухудшать читаемость кириллицы.

==================================================
18. CORNER RADII SYSTEM
==================================================

Сейчас слишком много элементов с радиусами 24–32dp.

Ввести иерархию радиусов.

Рекомендуемая система:

small controls: 12dp
small cards: 16dp
standard cards: 20dp
hero card: 28–32dp
pill/chip: fully rounded

Не использовать одинаковый огромный radius почти везде.

==================================================

==================================================

Текущую палитру сохранить.

Не добавлять новые яркие цвета.

Примерно:

#F4EEEC

Не использовать dynamic wallpaper colors, если они ломают фирменную палитру Ritela.

==================================================
28. DEFINITION OF DONE
==================================================

UI polish считается завершённым только если:

- приложение собирается;
- текущая функциональность не сломана;
- navigation работает;
- light/dark проверены;
- крупный шрифт проверен;
- calendar usable;
- period logging стал быстрее;
- settings выглядят законченными;
- графики выглядят как consumer product, а не debug dashboard;
- Home стал легче;
- число лишних карточек уменьшилось;
- палитра Ritela сохранена;
- orbit motif выглядит осмысленно;
- нет regression по accessibility.
