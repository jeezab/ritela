# Экспорт и импорт

Дневник 2026-10-08: шесть фиксированных тегов выделений хранятся в существующем поле custom (`discharge`: DRY/STICKY/CREAMY/WATERY/CLEAR_STRETCHY/UNUSUAL); текущий backup payload v2 уже переносит эти значения и layout без нового формата. Новые defaults mood/discharge/sex/energy применяются при отсутствии сохранённой структуры; пользовательские layouts и старые Pain/Flow записи не сбрасываются. Отдельный исторический registry сохраняет корректное преобразование встроенных значений при редактировании дня.

Настройки → Экспорт данных → необязательный пароль и повтор → системный выбор файла. Импорт: выбрать `.ritela`, ввести пароль (или оставить пустым для открытой копии), посмотреть количество записей и подтвердить. Пароль не сохраняется; его восстановление не предусмотрено. Файл переносится между устройствами без аккаунта; любой непустой пароль включает шифрование, пустой — открытый JSON.

Копия содержит все месячные (UUID, даты, createdAt/updatedAt), отметки дня, включая секс, заметки, пользовательские теги и выбранную иконку, а также сохранённую структуру дневника. Язык, тема и legacy presets не входят: импорт сохраняет настройки устройства. Текущая реализация импортирует только собственный формат, без CSV/чужих трекеров. Merge сохраняет существующие записи, пропускает полностью одинаковые и отменяет всю транзакцию при конфликте UUID/дат/отметки дня/структуры дневника. Замена базы не реализована; удаление текущих данных не требуется.

Внешний JSON: format=`ritela.backup`, version=1, iterations=600000, salt/iv/data в Base64. Внутренний JSON version=2 содержит массивы periods/days и journal; чтение старой version=1 сохранено. Открытая копия: format=ritela.backup.plain, version=1, data — внутренний JSON объект. Открытый файл не защищён паролем или проверкой подлинности, но проходит те же проверки структуры и дат. Применяется AES-256-GCM, tag 128 бит, случайные salt 16 байт и IV 12 байт, AAD=`ritela.backup:1`; ключ PBKDF2-HMAC-SHA256, 600000 итераций. Это выбранная стандартная схема, не собственный шифр. Work factor соотнесён с [OWASP PBKDF2 guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html); пароль остаётся важной частью защиты.

Пароль необязателен; минимальной и максимальной длины в форме нет. Повтор должен совпадать. Массивы символов/производного ключа очищаются по завершении; managed-memory строки JSON/поля UI нельзя гарантированно стереть из heap. Потерянный пароль делает копию недоступной. База на устройстве пока не зашифрована. Сам факт/размер файла и имя с датой видны выбранному файловому провайдеру. Пользователь может выбрать облачный провайдер в системном picker; приложение само ничего не отправляет.

Ограничения: файл ≤3 MiB, plaintext ≤2 MiB, ≤10000 periods и ≤10000 day logs; версии и work factor проверяются до KDF. Проверяются UUID, даты/пересечения, timestamps, enum/сочетания отметок, идентификаторы пользовательских тегов, структуру дневника и длину заметки. Неверный пароль и повреждение ciphertext не открывают preview. Все изменения Room проходят единую транзакцию. Доступ к файлам через [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files), без широких storage permissions. UI не делает persistable URI grants, временный доступ нужен только для текущей операции.

JVM-тесты проверяют round-trip в другую базу, сохранность дат/UUID/заметок, повторный merge, неверный пароль, изменение ciphertext, rollback конфликтов, будущие дни, неизвестную версию, чрезмерный work factor/размер и короткий пароль. Системный файловый picker, поведение облачных провайдеров и медленный телефон требуют device smoke test.
